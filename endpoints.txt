===========================================================
  ZAPASYA - DOCUMENTACIÓN DE ENDPOINTS EXTERNOS
===========================================================

SISTEMAS DESTINO:
  1. Sistema de Dashboard Externo (Payments / Shipping)
  2. Sistema de Admin Externo

AUTENTICACIÓN COMÚN (para ambos sistemas):
  Header: buyer-key
  Valor:  (el valor de la variable de entorno BUYER_SECRET)
  Si la clave es inválida → 403 "Clave inválida"

BASE URL:
  https://proyecto-c-buyer-dev-squad.vercel.app

===========================================================
  1. SISTEMA DE DASHBOARD EXTERNO
     (Payments App / Shipping App)
===========================================================

Estos endpoints son para que sistemas externos (ej. pasarela de
pagos, app de logística) consulten y actualicen el estado de
las órdenes.

-----------------------------------------------------------
1.1  GET /api/orders
-----------------------------------------------------------
  Propósito:  Consultar órdenes de clientes.
  Auth:       buyer-key header

  Query Params (opcionales):
    id      - Filtrar por ID de orden específica.
    status  - Filtrar por estado.
              Valores: PENDING | PAID | SHIPPED | DELIVERED
    page    - Número de página (default: 1)
    limit   - Items por página (default: 5, max: 100)

  Respuesta (sin id):
    {
      "data": [ ...ordenes... ],
      "pagination": {
        "page": 1,
        "limit": 5,
        "totalItems": 50,
        "totalPages": 10
      }
    }

  Respuesta (con id):
    { ...orden con items y productos... }

  Si no encuentra la orden → 404 { "error": "Order not found" }

  Ejemplos:
    curl -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/orders"

    curl -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/orders?id=abc123"

    curl -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/orders?status=PAID&page=1&limit=10"

-----------------------------------------------------------
1.2  PATCH /api/orders/[id]/status
-----------------------------------------------------------
  Propósito:  Actualizar el estado de una orden.
              Usado por Payments (PAID) y Shipping (SHIPPED, DELIVERED).
  Auth:       buyer-key header

  Body (JSON):
    {
      "status": "PAID" | "SHIPPED" | "DELIVERED"
    }

  Respuesta:
    { ...orden actualizada... }

  Ejemplo:
    curl -X PATCH \
      -H "buyer-key: MI_SECRET" \
      -H "Content-Type: application/json" \
      -d '{"status":"PAID"}' \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/orders/abc123/status"

  Scripts de simulación incluidos en el proyecto:
    npx tsx status-paid.ts <ORDER_ID>
    npx tsx status-shipped.ts <ORDER_ID>
    npx tsx status-delivered.ts <ORDER_ID>


===========================================================
  2. SISTEMA DE ADMIN EXTERNO
     (Panel administrativo)
===========================================================

Todos los endpoints de admin requieren:
  Header: buyer-key (con el valor de BUYER_SECRET)

-----------------------------------------------------------
2.1  GET /api/admin/dashboard
-----------------------------------------------------------
  Propósito:  Obtener estadísticas generales para el dashboard.

  Respuesta:
    {
      "totalUsers":       number,     // total de usuarios registrados
      "totalOrders":      number,     // total de órdenes
      "totalProducts":    number,     // total de productos
      "revenue":          number,     // ingresos totales (órdenes PAID)
      "pendingOrders":    number,     // órdenes pendientes
      "recentOrders":     [ ... ],    // últimas 8 órdenes con usuario y productos
      "topProducts":      [ ... ],    // top 5 productos más vendidos
      "topSellers":       [ ... ],    // top 5 usuarios con más órdenes
      "dailySales":       [ ... ]     // ventas diarias (últimos 30 días)
    }

  dailySales: array de { date: "YYYY-MM-DD", revenue: number, orders: number }

  Ejemplo:
    curl -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/dashboard"

-----------------------------------------------------------
2.2  GET /api/admin/sellers
-----------------------------------------------------------
  Propósito:  Listar todos los vendedores.

  Respuesta:
    { "data": [ ...vendedores... ] }

  Ejemplo:
    curl -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/sellers"

-----------------------------------------------------------
2.3  GET /api/admin/sellers/[id]
-----------------------------------------------------------
  Propósito:  Obtener un vendedor por ID.

  Respuesta:
    { ...vendedor... }

  Si no encuentra → 404 { "error": "Seller not found" }

  Ejemplo:
    curl -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/sellers/abc123"

-----------------------------------------------------------
2.4  GET /api/admin/products
-----------------------------------------------------------
  Propósito:  Listar productos con filtros y paginación.

  Query Params (opcionales):
    category       - Filtrar por categoría
    brand          - Filtrar por marca
    minPrice       - Precio mínimo
    maxPrice       - Precio máximo
    search         - Búsqueda por nombre o marca
    page           - Número de página (default: 1)
    limit          - Items por página (default: 10, max: 100)
    includeSeller  - "true" para incluir datos del vendedor

  Respuesta:
    {
      "data": [ ...productos... ],
      "pagination": {
        "page": 1,
        "limit": 10,
        "totalItems": 100,
        "totalPages": 10
      }
    }

  Ejemplos:
    curl -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/products"

    curl -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/products?category=Zapatillas&page=1&limit=20"

    curl -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/products?search=nike&minPrice=50&maxPrice=200"

-----------------------------------------------------------
2.5  GET /api/admin/products/[id]
-----------------------------------------------------------
  Propósito:  Obtener un producto por ID.

  Respuesta:
    { ...producto... }

  Si no encuentra → 404

  Ejemplo:
    curl -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/products/abc123"

-----------------------------------------------------------
2.6  GET /api/admin/orders
-----------------------------------------------------------
  Propósito:  Listar órdenes con filtros y paginación.

  Query Params (opcionales):
    id      - Filtrar por ID de orden
    status  - Filtrar por estado (PENDING | PAID | SHIPPED | DELIVERED)
    page    - Número de página (default: 1)
    limit   - Items por página (default: 10, max: 100)

  Respuesta (sin id):
    {
      "data": [ ...ordenes... ],
      "pagination": { "page", "limit", "totalItems", "totalPages" }
    }

  Respuesta (con id): { ...orden con usuario y items+productos... }
  Si no encuentra → 404

  Ejemplo:
    curl -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/orders?status=PENDING"

-----------------------------------------------------------
2.7  GET /api/admin/orders/[id]
-----------------------------------------------------------
  Propósito:  Obtener una orden con detalles completos.

  Respuesta:
    {
      ...orden...,
      "user": { "firstName", "lastName", "email" },
      "items": [ { ...item..., "product": { ... } } ]
    }

  Si no encuentra → 404

  Ejemplo:
    curl -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/orders/abc123"

-----------------------------------------------------------
2.8  PATCH /api/admin/orders/[id]
-----------------------------------------------------------
  Propósito:  Actualizar una orden (datos, estado, items).

  Body (JSON, todos opcionales):
    {
      "firstName": "string",       // nombre del comprador
      "lastName":  "string",       // apellido del comprador
      "email":     "string",       // email del comprador
      "total":     number,         // total de la orden
      "status":    "PENDING" | "PAID" | "SHIPPED" | "DELIVERED",
      "createdAt": "ISO date string",
      "items": [                   // items de la orden
        { "quantity": number, "price": number }
      ]
    }

  Respuesta:
    { ...orden actualizada con usuario y items+productos... }

  Si no encuentra → 404

  Ejemplo:
    curl -X PATCH \
      -H "buyer-key: MI_SECRET" \
      -H "Content-Type: application/json" \
      -d '{"status":"SHIPPED","total":150.00}' \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/orders/abc123"

-----------------------------------------------------------
2.9  DELETE /api/admin/orders/[id]
-----------------------------------------------------------
  Propósito:  Eliminar una orden.

  Respuesta:
    { "success": true }

  Si no encuentra → 404

  Ejemplo:
    curl -X DELETE -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/orders/abc123"

-----------------------------------------------------------
2.10  GET /api/admin/users
-----------------------------------------------------------
  Propósito:  Listar usuarios con búsqueda y paginación.

  Ejemplo:

-----------------------------------------------------------
2.11  GET /api/admin/users/[id]
-----------------------------------------------------------

  Respuesta:

-----------------------------------------------------------
2.12  PATCH /api/admin/users/[id]
-----------------------------------------------------------
  Propósito:  Actualizar datos de un usuario.

  Body (JSON, todos opcionales):

      "firstName":   "string",
      "lastName":    "string",
      "email":       "string",
      "createdAt":   "ISO date string",
      "orderCount":  number
    }

  Respuesta:

  Si no encuentra → 404

  Ejemplo:
    curl -X PATCH \
      -H "buyer-key: MI_SECRET" \
      -H "Content-Type: application/json" \

      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/users/abc123"

-----------------------------------------------------------
2.13  DELETE /api/admin/users/[id]
-----------------------------------------------------------
  Propósito:  Eliminar un usuario.

  Respuesta:
    { "success": true }

  Si no encuentra → 404

  Ejemplo:
    curl -X DELETE -H "buyer-key: MI_SECRET" \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/users/abc123"

-----------------------------------------------------------
2.14  PATCH /api/admin/users/[id]/status
-----------------------------------------------------------
  Propósito:  Suspender o activar un usuario.

  Body (JSON):
    {
      "status": "SUSPENDED" | "ACTIVE"
    }

  Respuesta:
    { "success": true, "status": "SUSPENDED" | "ACTIVE" }

  Si el status es inválido → 400 { "error": "Invalid status..." }
  Si no encuentra el usuario → 404

  Ejemplo:
    curl -X PATCH \
      -H "buyer-key: MI_SECRET" \
      -H "Content-Type: application/json" \
      -d '{"status":"SUSPENDED"}' \
      "https://proyecto-c-buyer-dev-squad.vercel.app/api/admin/users/abc123/status"
